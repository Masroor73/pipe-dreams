# Pipe Dreams — Rubric Traceability

A requirement is not considered satisfied merely because it is described in documentation. It must be visible in code, output, or the demo.

## Autonomous Reasoning + Data-Driven Decisions — 30%

Evidence:
- Plan V1;
- rolling replay;
- diagnosis;
- named candidate tests;
- accept/reject gate;
- V2 or V1 retained;
- `agent_log.jsonl`;
- named baseline.

Demo proof:
> "The software decided X from data Y, tested change Z, and accepted/rejected it because of these measured results."

## Real Industrial Problem & Relevance — 20%

Evidence:
- municipal water asset-management/integrity user;
- public break + pipe data;
- limited inspection capacity;
- explicit evidence gaps;
- mentor / practitioner validation line if available.

## Execution & Architecture — 20%

Evidence:
- React app;
- FastAPI API;
- Python engine;
- stable artifacts;
- real output;
- architecture diagram;
- tests;
- no duplicated ranking logic.

## Commercialization — 15%

Evidence:
- pilot with a municipal asset/integrity team;
- integrates beside GIS/EAM/work-order/inspection systems;
- replaces public-data proxies with verified utility records;
- scalable through data adapters + policy config.

## Presentation & Demo — 15%

Demo sequence:
1. baseline;
2. V1;
3. validation;
4. candidate test;
5. accept/reject;
6. V2 or retained V1;
7. three rank/action changes;
8. escalation;
9. not-covered limitation;
10. measured result/value.

# Case 8 Traceability

Must show:

- consequence-aware planning;
- Top-25 comparability;
- plan → score → revise in code;
- at least three assets/places that rose or fell;
- dropped-coordinate count;
- named end user;
